Check the well total before touching the clone

max_objects_per_well: int = 100

if well_id and objects_per_well.get(well_id, 0) >= max_objects_per_well:
    continue

objects_per_well[well_id] += object_count

The final addition above applies only to a named well. The implementation initializes its total on the first count.

At or above target

The check uses ≥, not equality. The final acquired image can take the total above the target; it is not truncated.

Well IDs persist

Totals remain valid even if a well appears again later in the list. A new run starts with empty totals.

No shared unknown well

Unassigned positions have no cumulative limit. With acquisition disabled, nothing is counted, so all positions remain eligible.

The target must be positive; invalid values stop the script before connecting to ZEN. Counts and skip decisions are logged.

Ranges include both endpoints and use zero-based indices. Omitted axes select their first index. The current acquisition loop calls the helper with its defaults.

One plane only

Non-singleton S/T/C/Z axes raise an error. A trailing grayscale sample axis is removed; RGB is rejected.

Strict threshold

Pixels must be brighter than the Otsu threshold. A constant background does not become foreground.

Existing cleanup

ArrayProcessor.label_objects removes components of at most ten pixels, excludes borders, and uses diagonal connectivity.

Diagnostics do not require image acquisition

The folder identifies the run; the filename identifies the field

P004 denotes the fourth position in the original list, not necessarily the fourth acquisition. Skipped positions leave index gaps. Missing well assignments use Unassigned. ZEN's returned filename takes precedence.

Safety checks reject an existing run folder, an existing requested source CZI, invalid or reused returned output names, empty diagnostic XML, missing source files, and occupied destination paths.
